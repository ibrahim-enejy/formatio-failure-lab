# Scenario 02: Upstream Connection Starvation (The 15-Second Hanging Webhook)

> **Failure Classification:** Latency Cascade / Socket & Connection Exhaustion  
> **Affected Framework:** Node.js (Event Loop & Socket Pool)  
> **Difficulty:** Intermediate  

---

## 1. Failure Anatomy

In distributed systems, slow third-party dependencies (payment gateways, fraud APIs, LLM calls) without strict timeouts are more lethal than crashes. 

When an upstream endpoint hangs for 15+ seconds, incoming concurrent requests consume reverse-proxy worker connections (Nginx/Traefik/Cloudflare), resulting in cascading `504 Gateway Timeout` errors for healthy endpoints across the service.

```text
[Incoming Clients] ──(HTTP)──> [Load Balancer / Ingress]
                                        │
                                (Worker Pool Full)
                                        │
                              POST /api/lab/scenarios/02-hang
                                        │
                         (Hanging 15s in setTimeout / 3rd party API)
                                        ↓
                  [All other health checks & routes time out (504)]
```
