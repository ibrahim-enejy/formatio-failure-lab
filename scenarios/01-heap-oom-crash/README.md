# Scenario 01: Unbounded Heap Allocation (OOM Kill & Crash Loop)

> **Failure Classification:** Memory Leak / Out-Of-Memory (OOM)  
> **Affected Framework:** Node.js (V8 Heap Exhaustion)  
> **Difficulty:** Beginner  

---

## 1. Failure Anatomy

In production microservices, memory leaks often don't manifest immediately. A batch processing loop or unbuffered file upload continually appends binary buffers to an in-memory array. 

When container memory limits (e.g. `512MB` or `1GB` cgroups limit) are exceeded, the Linux kernel invokes the `oom-killer` with `SIGKILL` (`exit code 137`).

```text
[HTTP Request] → POST /api/lab/scenarios/01-oom
    ↓
Allocating 10MB chunks continuously...
    ↓
V8 Heap Limit Reached (~1.4GB) or Linux CGroup Limit Exceeded
    ↓
Linux Kernel sends SIGKILL (Exit 137)
    ↓
Container crashes. Orchestrator triggers restart loop.
```
